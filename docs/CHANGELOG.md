## How to Update This File

When making changes to the project, follow these steps to update the changelog:

1. **Determine the version number** based on the type of change:
   - **Patch (0.0.x)**: Bug fixes, minor improvements
   - **Minor (0.x.0)**: New features, backward-compatible changes
   - **Major (x.0.0)**: Breaking changes, significant updates

2. **Add a new entry** at the top of the file with the appropriate version number and date.

3. **Categorize changes** under the appropriate section:
   - **Added**: New features
   - **Changed**: Existing features modified
   - **Deprecated**: Soon-to-be removed features
   - **Removed**: Features removed
   - **Fixed**: Bug fixes
   - **Security**: Security-related changes

4. **Include detailed descriptions** of each change with enough detail for users to understand the impact.

5. **Update the version history** section at the bottom of the file.

## Contributing to Changelog

5. **Update the version history** when appropriate

## Release Process

When releasing a new version:

1. **Update the changelog** with all changes since the last release
2. **Update the version number** in `package.json`
3. **Create a release** on GitHub
4. **Announce the release** to the community
5. **Update the roadmap** if necessary
